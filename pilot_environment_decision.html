SAP Runs on SAP — EC Benefits Pilot Program

Pilot Environment: Production vs. QA

A decision reference for choosing the testing environment. Each option has distinct implications for scenario coverage, participant data, and post-pilot operational requirements.

⚠

Not yet formally decided. The pilot options described in the companion document are modeled on a QA / lower environment assumption. This decision must be confirmed before December planning begins and will affect which pilot approach options are viable.

Production

Live Environment

Advantages
  • No separate environment approval required to begin
  • Carrier file validation is possible — downstream data can be tested end-to-end
  • Highest real-world signal — participants experience the actual product as it will exist at GA
  • Compatible with time-elapsed testing (change in cycle 1, follow-up in cycle 2)
Constraints
  • Participants' changes are real and permanent until data refresh Elections made in EC Benefits during the pilot will be live data
  • Requires a full data refresh before GA — pilot activity must be overwritten prior to August 2027 See critical requirement below
QA / Lower Env

Test Environment

Advantages
  • Fully controlled — any test scenario can be assigned independent of real life events
  • No risk to participant's real benefit data — all changes are to test data only
  • Compatible with all three pilot options (Coffee Drip, Visibility Path, Hybrid)
  • Supports time-elapsed testing without real data consequences
  • No data refresh required before GA — test data does not carry forward
Constraints
  • Communicating QA environment selection may surface stakeholder objections — raise and resolve before December to avoid blocking the path Who holds approval authority and what does sign-off require?
🔴

Critical Requirement — Production Environment Only: Pre-GA Data Refresh

Production only

If Production is selected as the pilot environment, a full data refresh is required before EC Benefits goes live to all US SAP employees in August 2027. Without this refresh, all activity made by pilot participants — including test elections and changes — will persist as live data into the GA environment.

  • Benefitfocus data overwrites EC Benefits to establish a clean, accurate baseline for all US employees
  • Pilot test activity does not carry forward — participants' GA experience will reflect their Benefitfocus record, not pilot changes
  • Must be planned and scheduled in advance — this is not an automatic step
  • Timing: pre-August 2027; exact date to be confirmed as part of GA readiness planning
  • Failure to execute this refresh before GA would result in incorrect benefit data for pilot participants at launch
